# Simple OS Emulator

Эмулятор командной оболочки UNIX-подобной операционной системы, написанный на Go.

Приложение предоставляет графический терминал с виртуальной файловой системой,
поддержкой команд оболочки, стартовых скриптов и параметров командной строки.

## Возможности

- графический интерфейс терминала на Fyne;
- виртуальная файловая система, загружаемая из JSON;
- все изменения VFS выполняются только в памяти;
- абсолютные и относительные пути;
- поддержка `.`, `..`, `~`;
- история введённых команд;
- навигация по истории с помощью стрелок вверх и вниз;
- выполнение нескольких вставленных команд;
- запуск команд из стартового скрипта;
- комментарии `//` в стартовых скриптах;
- настраиваемое приглашение командной строки;
- вывод команд и результатов выполнения в формате терминального диалога.

## Поддерживаемые команды

### `ls`

Выводит содержимое директории.

```bash
ls
ls /home/user
ls /home/user/docs
ls /home/user /tmp
```

Можно передавать несколько путей одновременно.

### `cd`

Изменяет текущую директорию.

```bash
cd /home/user/docs
cd ..
cd ~
cd -
```

Если команда вызывается без аргументов, текущая директория изменяется на
`/home/user`.

`cd -` возвращает пользователя в предыдущую директорию.

### `pwd`

Выводит путь к текущей директории.

```bash
pwd
```

### `whoami`

Выводит имя текущего пользователя.

```bash
whoami
```

Имя пользователя определяется из приглашения оболочки как часть до символа `@`.

### `rev`

Переворачивает символы в строках.

Чтение файла из VFS:

```bash
rev /home/user/notes.txt
```

Можно передавать несколько файлов:

```bash
rev file1.txt file2.txt
```

При запуске без аргументов команда переходит в интерактивный режим:

```bash
rev
```

В этом режиме каждая введённая строка выводится в обратном порядке.

Для выхода из режима используется `Ctrl+D`.

### `mv`

Перемещает или переименовывает файлы и директории внутри VFS.

Переименование:

```bash
mv notes.txt renamed.txt
```

Перемещение в директорию:

```bash
mv notes.txt /home/user/docs
```

Перемещение с переименованием:

```bash
mv notes.txt /home/user/docs/renamed.txt
```

Если файл назначения уже существует, он заменяется исходным файлом.

Корневую директорию перемещать нельзя. Также нельзя переместить директорию
в саму себя или в одну из её дочерних директорий.

Все изменения выполняются только в памяти и не изменяют исходный JSON-файл VFS.

### `help`

Без аргументов выводит список доступных команд:

```bash
help
```

Для получения подробной информации о конкретной команде:

```bash
help ls
help rev
help mv
```

### `exit`

Закрывает эмулятор.

```bash
exit
```

## Параметры запуска

Эмулятор поддерживает параметры командной строки:

- `-vfs` — выбор виртуальной файловой системы;
- `-prompt` — пользовательское приглашение оболочки;
- `-script` — путь к стартовому скрипту.

### `-vfs`

По умолчанию используется VFS `simple`.

Пример:

```bash
go run ./cmd -vfs deep
```

VFS находятся в каталоге:

```text
data/vfs/
```

В проекте используются:

```text
minimal.json
simple.json
deep.json
```

### `-prompt`

Изменяет приглашение командной строки.

По умолчанию:

```text
user@localhost
```

Пример:

```bash
go run ./cmd -prompt admin@emulator
```

В терминале приглашение будет выглядеть примерно так:

```text
admin@emulator:~$
```

### `-script`

Запускает стартовый скрипт при старте эмулятора.

Пример:

```bash
go run ./cmd -vfs deep -script data/startup/final-test.txt
```

Стартовые скрипты поддерживают комментарии:

```text
// comment
ls
cd /home/user
pwd
```

При выполнении скрипта в окне отображаются как команды, так и результаты их
выполнения.

## Запуск

Требуется установленный Go.

Установка зависимостей:

```bash
go mod download
```

Запуск с настройками по умолчанию:

```bash
go run ./cmd
```

Запуск с другой VFS:

```bash
go run ./cmd -vfs deep
```

Запуск с пользовательским prompt:

```bash
go run ./cmd -prompt admin@localhost
```

Запуск со стартовым скриптом:

```bash
go run ./cmd -vfs deep -script data/startup/final-test.txt
```

Параметры можно комбинировать:

```bash
go run ./cmd \
    -vfs deep \
    -prompt admin@localhost \
    -script data/startup/final-test.txt
```

## Виртуальная файловая система

Источником VFS являются JSON-файлы из директории:

```text
data/vfs/
```

Пример директории:

```json
{
  "name": "docs",
  "type": "dir",
  "children": {}
}
```

Пример файла:

```json
{
  "name": "notes.txt",
  "type": "file",
  "content": "Some personal notes"
}
```

Для двоичных данных содержимое может храниться в Base64.

После загрузки JSON файловая система находится в памяти программы.
Команды вроде `mv` изменяют только её состояние в памяти и не перезаписывают
исходный JSON-файл.

## Стартовые скрипты

Скрипты для проверки команд находятся в:

```text
data/startup/
```

В том числе:

```text
commands-test.txt
config-test.txt
final-test.txt
vfs-test.txt
```

`final-test.txt` содержит итоговую проверку реализованных команд,
различных режимов работы и обработки ошибок.

## Скрипты запуска

Скрипты реальной операционной системы находятся в:

```text
data/scripts/
```

Они используются для проверки различных вариантов запуска приложения,
параметров командной строки и VFS.

Примеры:

```text
run-default.sh
run-custom-prompt.sh
run-with-script.sh
run-minimal.sh
run-simple.sh
run-deep.sh
```

## Пример работы

```text
user@localhost:~$ pwd
~

user@localhost:~$ ls
docs   downloads   notes.txt   todo.txt

user@localhost:~$ cd docs

user@localhost:~/docs$ ls
ideas.txt   project.txt   report.md

user@localhost:~/docs$ rev project.txt
rotalume SO elpmiS
noitatnemelpmi 4 egatS

user@localhost:~/docs$ cd ..

user@localhost:~$ mv notes.txt docs/notes.txt

user@localhost:~$ ls docs
ideas.txt   notes.txt   project.txt   report.md
```

## Тестирование

Для итоговой ручной проверки можно запустить:

```bash
go run ./cmd -vfs deep -script data/startup/final-test.txt
```

Скрипт проверяет основные режимы работы команд и обработку ошибок.

Интерактивный режим `rev` с выходом через `Ctrl+D` проверяется вручную.
